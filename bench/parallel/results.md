## Method

`make bench-parallel` builds the release binary and the `bench_parallel` example, runs `bench/parallel/run.ts`, then renders this file with `bench/parallel/report.ts`. Everything happens in one directory under `$TMPDIR`, removed on exit (also on Ctrl-C), and the dependency layer volumes it created are deleted at the end.

- **Source.** Each repository is fetched at its pinned commit (depth 1) into a bare repository. That fetch is not timed: it stands in for the clone an agent setup already has.
- **Status quo.** For each N: `git worktree add --detach` N times, one after another in both modes (they share the repository's locks and take well under a second each), then the install in every worktree, either one at a time (sequential) or as many at once as the machine has cores (parallel). Ready is the wall time from the first `worktree add` to the last install finishing. This is the setup claude-squad and Conductor run per agent session (a worktree, then the project's install or setup script), so those tools have the same cost and are not measured separately.
- **Cold and warm.** Each package manager gets dedicated cache directories in the temporary directory (`npm_config_cache`, pnpm's `--store-dir` and XDG directories); the user's caches are never read or cleared. Cold empties them before each run, so every package comes from the registry; warm runs right after a cold run of the same size, with every package already cached. npm runs with `--no-audit --no-fund` and lifecycle scripts enabled, as a developer would run it.
- **Disk.** One `du -sk` over all N environments, which counts each hard-linked file once: allocated blocks and, with `-A` (`--apparent-size` on Linux), apparent size. `du` cannot see APFS clones, so the change in free space (`df`) is recorded too; it is noisy because other processes write to the same disk. Before each run the harness estimates the space it needs from the runs so far and skips it if less than a reserve would remain; skipped runs say so and their figures are extrapolated linearly from the largest measured N and marked as such.
- **Repetitions.** N ≤ 10 run three times and report the median ready time; larger N run once. N = 1 has no parallel mode.
- **Aver.** The `bench_parallel` example (`crates/aver/examples/bench_parallel.rs`, release build) imports the commit into a fresh `$AVER_HOME`, runs one `node -e 0` sandbox, which probes the dependency layer and builds it if it is missing (cold deletes the layer's volume first), runs a second one to time a bare sandbox, and opens N workspaces for each N. Ready for N agents is import + first sandbox + opening N workspaces. Then up to four workspaces each get a one-file edit, so no result can come from a cache, and run the project's check at the same time against the one layer.
