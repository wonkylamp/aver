# Disk workspace benchmark

Generated by `bench/workspace-disk.sh` on 2026-10-13 (release build); raw results in [results/disk.json](results/disk.json) and [results/disk-copy.json](results/disk-copy.json). Rerun the script to regenerate them.

**Machine.** MacBookPro18,3, Apple M1 Pro, 8 cores, 16 GiB RAM, macOS 27, APFS. Other agents' builds and Docker tests ran throughout, at a load average of 38-58 on 8 cores, so every time below is an upper bound. Free-space deltas also absorb other processes' writes: an earlier run on the same host measured 2.9 MB per date-fns directory where this one measured 4.4 MB.

**What is measured.** For each repository the benchmark imports the commit, then materializes workspace directories one after another with `Workspaces::materialize` (open, clone, farm, `.aver/`, stat seed, rows). The first directory on a base also writes the checkout and, with dependencies, adopts the store. It then times 30 syncs of an unchanged directory, 5 syncs after editing 10 files, and compares `git worktree add --detach` (no dependency install) on the same commit. Disk is the volume's free-space change divided by the count, because `du` counts cloned blocks once per clone.

## Against the design targets

- **Create under 1 s warm**: met. p95 is 129 ms for date-fns and 428 ms for 16k files with a 20k-file farm, against 0.4-2.8 s for a worktree before any `npm install`. The copy path matches a worktree's time for the sources, and its `node_modules` is still a farm.
- **Cold base under 2 s excluding first deps**: met for date-fns (437 ms). The synthetic first directory (5.1 s) includes adopting the 20k-file store, which the benchmark does not separate from writing the 16k-file checkout.
- **Disk under 1% of a worktree plus `npm ci`**: not met as measured. A clone shares every data block, but APFS still writes per-file metadata, roughly 1.5-2 KB per file: 4.4 MB per date-fns directory against 16.1 MB for a worktree with no install, and 7.3 MB for the synthetic repository against 80 MB plus its `node_modules` (under 5% once the install is counted). With `copy`, a directory costs about as much as a worktree's sources.
- **Sync p95 on a 100k-file repository under 0.5 s**: not measured; 16k files sync in 141 ms p95 on this loaded host.

## For the worktree comparison

The parallel worktree-versus-Aver benchmark can create N directories with the CLI, which prints JSON with per-directory timings:

```bash
AVER_HOME=/tmp/aver-bench aver init
AVER_HOME=/tmp/aver-bench aver workspace new <repo> --rev <commit> --count <N> --json [--no-deps]
```
