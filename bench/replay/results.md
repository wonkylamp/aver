# Replay study: real agent pull requests through `aver ci`

Generated by `node bench/replay/compare.ts` from `results-r6.jsonl` (this rerun), `results.jsonl` (the first run, rendered in [results-r4.md](results-r4.md)) and the hand triage in `triage-r6.json`. [findings.md](findings.md) explains each failure class and what round 6 changed.

## Setup

- **Aver commit:** `3f8002125962`, `89ddcd67a668`, `99e612b84879` (round 6, `aver ci`, release build). The first run used `1a0727d8642c`.
- **Date:** 2026-10-13.
- **Dataset:** pull requests from AIDev (Hao Li, Haoxiang Zhang, Ahmed E. Hassan; https://huggingface.co/datasets/hao-li/AIDev, CC-BY-4.0), as listed in [manifest.json](manifest.json). Code was fetched read-only from the public repositories.
- **Machine and invocation:** as in the first run (results-r4.md): Apple M1 Pro, Docker Desktop with 8 CPUs and 8 GiB, `runc` sandboxes, `aver ci --repo <bare clone> --base <recorded base> --head <PR head> --home <one fresh persistent home> --fail-on never --sandbox auto`, one pull request at a time, 30-minute limit each. Dependency volumes from a nine-PR pilot of this build were reused (they are keyed by content); the Aver home started empty, so no run was a cache hit from an earlier build.
- **What round 6 changed for these runs:** `aver ci` lists possible secrets and imports files over 64 MiB empty instead of refusing the import; it compares with the merge base when the recorded base is not an ancestor of the head; the default check adds the test runner's reporter (node:test, Vitest, Jest, Mocha, tap) and runs `prepare` and, when the package's entry points are build output, `build` first; `node_modules` is writable through links over the read-only layer; dependency install scripts run in a network-less rebuild; and a command-level check red on both sides is `BLOCKED_NOT_OWN`, not `PASS`.
- **Load:** the replay waits before each pull request until the 1-minute load average is below 20 (`--max-load 20`, recorded as `load_at_start`). The first six rows ran before that gate existed, right after the run started on an idle machine; the machine then slept mid-run, and the runs in flight while it was asleep or heavily loaded were discarded and rerun.
- **Useful receipt:** the project's tests ran on both sides with per-test results: the receipt has entries for single tests (both sides wrote a machine-readable report) and at least one test passed on both sides. This is the round-6 goal metric. For the first run, the comparable number is the hand-triaged informative receipts (every first-run receipt was command-level).

### Triage notes

- **lirantal/npq#375** (tests need network: the runner crashes): A test resolves `gmail.com`; the rejected DNS promise is unhandled and kills the Jest process on both sides, so Jest never writes its JSON report and the check stays command-level. Red on both sides, so the verdict is now BLOCKED_NOT_OWN instead of the first run's PASS.
- **ekalinin/sitemap.js#455** (native binding needs the network): Jest's resolver `unrs-resolver` needs a `linux-arm64` binding the Mac-made lockfile does not list; `napi-postinstall` downloads it, which fails without network both in the network-less rebuild and at test time (`Preset ts-jest not found`). Command-level, red on both sides. FAIL_OWN comes only from `judging::jest.config.cjs` (see the FAIL_OWN notes). These runs were served from the run cache of an attempt made while the machine was loaded; the failure is deterministic.
- **leonardsellem/n8n-mcp-server#33** (custom test script): `npm test` is `node --experimental-vm-modules run-tests.js`, a wrapper that spawns Jest, so Aver cannot add a reporter and the check stays command-level (it passes on both sides). An `aver.toml` with a Jest JSON report would give per-test results.
- **paralleldrive/cuid2#104** (custom test script): `npm test` runs riteway files with `node` directly (TAP on stdout, no report file), so the check is command-level. It fails at head: the base's copy of `src/index-test.js` expects `bufToBigInt` to return a BigInt, which the PR (BigInt replaced by bignumber.js) changed along with that test; upstream CI was green.
- **paralleldrive/cuid2#98** (custom test script): `npm test` runs a riteway file with `node` directly, so the check is command-level; it fails on both sides when the `esm` loader throws before any test runs (the first run's finding 12; the error is now visible), so the verdict is BLOCKED_NOT_OWN instead of PASS.
